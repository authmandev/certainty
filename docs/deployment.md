# Certainty — Deployment Guide

How to run Certainty V1 in production (BRD Milestone 9). Every command runs from the application root.

## 1. Server requirements

| Component | Requirement |
|---|---|
| PHP | 8.3 or newer (developed on 8.5), with `pdo_mysql` or `pdo_pgsql`, `mbstring`, `fileinfo`, `gd`, `intl`, `zip`, `bcmath` |
| Database | MySQL 8 / MariaDB 10.6+ or PostgreSQL 14+. SQLite is for development and tests only |
| Node.js | 20+ to build the frontend (`npm run build`). It is not needed at runtime |
| Queue backend | Redis (recommended) or the `database` driver |
| PDF renderer | Chromium or Chrome for Testing, plus `libnss3`, `libnspr4` and `libasound2`. You can use a Gotenberg or Cloudflare driver instead (see §6) |
| Process manager | Supervisor or systemd, for the queue worker |
| Cron | For the Laravel scheduler |
| Web server | Nginx or Apache with HTTPS, document root `public/` |

## 2. Environment configuration

Copy `.env.example` to `.env`, run `php artisan key:generate` once, and set the following.

| Variable | Production value |
|---|---|
| `APP_ENV` | `production` |
| `APP_DEBUG` | `false` (never `true` in production) |
| `APP_URL` | `https://your-domain` |
| `LOG_LEVEL` | `warning` or `error` |
| `DB_*` | Production database credentials |
| `SESSION_DRIVER` | `database` or `redis` |
| `SESSION_SECURE_COOKIE` | `true` |
| `QUEUE_CONNECTION` | `redis` or `database` (not `sync`) |
| `CACHE_STORE` | `redis` or `database`. Report PDFs use a cache lock, so the store must support locks |
| `MAIL_*` | A real mailer; password-reset emails depend on it |
| `CERTAINTY_STUDY_PRICE`, `CERTAINTY_CURRENCY` | Study price and currency (default 1200 SAR) |
| `CERTAINTY_DRAFT_DURATION_DAYS` | Draft lifetime (default 60) |
| `CERTAINTY_BANK_NAME`, `CERTAINTY_BANK_ACCOUNT_NAME`, `CERTAINTY_BANK_IBAN` | Account details shown to customers for the bank transfer |
| `CERTAINTY_CONTACT_EMAIL`, `CERTAINTY_CONTACT_PHONE` | Public contact details |
| `CERTAINTY_COMPANY_NAME` | Name on the report cover |
| `CERTAINTY_RECEIPTS_DISK`, `CERTAINTY_REPORTS_DISK` | Keep `local` (private) unless you configure a private S3 disk |
| `CERTAINTY_RECEIPT_MAX_KB` | Maximum receipt size (default 5120) |
| `LARAVEL_PDF_DRIVER` | `chrome` (default), `gotenberg` or `cloudflare` |
| `LARAVEL_PDF_CHROME_BINARY` | Absolute path to Chromium or `chrome-headless-shell` |
| `LARAVEL_PDF_CHROME_NO_SANDBOX` | `true` only inside containers that cannot use Chrome's sandbox |

Secrets live only in `.env`; nothing private is sent to the browser (BRD NFR-006).

## 3. First deployment

```bash
composer install --no-dev --optimize-autoloader
npm ci && npm run build
php artisan key:generate              # first deployment only
php artisan migrate --force
php artisan db:seed --class=ReferenceOptionSeeder --force
php artisan certainty:create-admin admin@your-domain --name="Platform admin"
php artisan optimize
php artisan certainty:check-production
```

`certainty:check-production` lists every check as OK, WARN or FAIL. Fix every FAIL before going live. Warnings usually mean client details (bank account, contact email) are still missing.

## 4. Every later deployment

```bash
php artisan down --render="errors::503"
git pull
composer install --no-dev --optimize-autoloader
npm ci && npm run build
php artisan migrate --force
php artisan db:seed --class=ReferenceOptionSeeder --force   # keeps dropdown lists current; safe to repeat
php artisan optimize
php artisan queue:restart
php artisan up
```

## 5. Background processes

**Scheduler.** Add a cron entry that runs every minute:

```cron
* * * * * cd /var/www/certainty && php artisan schedule:run >> /dev/null 2>&1
```

It runs:
- `studies:expire-drafts` every hour
- `auth:clear-resets` daily
- `queue:prune-failed` daily, keeping 30 days

**Queue worker.** Report PDFs are generated by a queued job. Example Supervisor configuration:

```ini
[program:certainty-worker]
command=php /var/www/certainty/artisan queue:work --sleep=3 --tries=3 --max-time=3600
user=www-data
numprocs=1
autostart=true
autorestart=true
stopwaitsecs=180
redirect_stderr=true
stdout_logfile=/var/www/certainty/storage/logs/worker.log
```

If the worker is down, a customer opening a report still gets it, because the download renders on demand. Background generation stops until the worker is back.

## 6. PDF renderer

**Chrome (default).** Install Chrome for Testing without root, or use the distribution's Chromium:

```bash
npx @puppeteer/browsers install chrome-headless-shell@stable --path /opt/chrome
sudo apt-get install -y libnss3 libnspr4 libasound2t64
```

Set `LARAVEL_PDF_CHROME_BINARY` to the printed path. Update it whenever you upgrade Chrome, because the version is part of the path.

**Alternatives.** These need no code change, only `.env`:
- `LARAVEL_PDF_DRIVER=gotenberg` with `GOTENBERG_URL`. This runs a Gotenberg Docker container alongside the app.
- `LARAVEL_PDF_DRIVER=cloudflare` with `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`. Study data is sent to Cloudflare for rendering.

The report embeds its own Arabic font (`resources/fonts`), so the server doesn't need Arabic fonts installed.

## 7. Web server notes

- Serve only `public/`. Receipts and reports are in `storage/app/private` and are served only through authorization-checked routes.
- Redirect HTTP to HTTPS. The app sends HSTS on HTTPS responses.
- Allow uploads up to the receipt limit, plus some headroom: `client_max_body_size 8m;` (Nginx), and `upload_max_filesize = 8M` and `post_max_size = 8M` (PHP).
- The health-check URL is `GET /up`.
- **Security headers.** These are set by `App\Http\Middleware\SecurityHeaders`: `X-Content-Type-Options`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy` and `Permissions-Policy`. A Content Security Policy is not set yet, because the root view uses inline scripts; add one at the web server if required.

## 8. Backup and recovery (BRD NFR-008)

What to back up:

| Data | Location | Why |
|---|---|---|
| Database | `DB_DATABASE` | Users, studies, inputs, payments, report snapshots, audit history |
| Private files | `storage/app/private` (`receipts/`, `reports/`) | Payment receipts and generated PDFs |
| Configuration | `.env` | Keep it in a password manager or secrets vault, not with the backups |

Recommended schedule:
- **Database:** a nightly dump, e.g. `mysqldump --single-transaction --routines certainty | gzip > certainty-$(date +%F).sql.gz`. Keep 14 daily and 8 weekly copies.
- **Private files:** a nightly incremental copy (`rsync -a --delete storage/app/private/ backup-host:/backups/certainty/private/`) or object-storage versioning.
- **Off site:** store copies off the application server, encrypted at rest.
- **Restore test:** once a month, restore the dump and files into a staging copy, then open a finalized study's report to confirm both are intact.

Reports can be rebuilt from their stored snapshots if a PDF file is lost. Set `pdf_path` to null on the `study_reports` row and the next download renders it again. Receipts cannot be recreated, so the file backup matters.

A package such as `spatie/laravel-backup` can automate this from the scheduler. It isn't installed, because adding a dependency needs approval.

## 9. Operations

| Task | Command |
|---|---|
| Create an administrator | `php artisan certainty:create-admin email@domain --name="..."` |
| Make an existing user an administrator | `php artisan certainty:create-admin email@domain --promote` |
| Check production readiness | `php artisan certainty:check-production` |
| Expire overdue drafts now | `php artisan studies:expire-drafts` |
| Retry failed jobs | `php artisan queue:retry all` |
| Logs | `storage/logs/laravel.log` |
